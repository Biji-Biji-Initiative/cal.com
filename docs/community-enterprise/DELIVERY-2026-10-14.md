## Why migration admission was added

The upstream v6.2-to-Cal.diy cleanup migrations remove routing-form/workflow and
domain-wide delegation data, impersonation/privacy columns and old webhook
trigger values. A previous restore rehearsal failed when comparing a removed
column. Treating that as a harmless comparison mismatch would miss actual data
loss for installations that use those features.

The source-owned SQL preflight is now required by the explicit packaged migrate
command. It rejects populated retired tables, non-default retired columns,
retired routing/instant-meeting trigger subscriptions, row-security concealment,
query/type/permission failures and a missing or modified preflight file. The
artifact manifest binds the preflight hash. Errors identify table/column names,
not stored identities, credential values or record contents. Normal web startup
still never migrates a database.

This is a bounded guard for the inspected migration chain, not a universal
classifier for future upstream SQL. Historical migration files/checksums were
not changed. Future destructive migrations require review and appropriate guard
coverage. The preflight transaction is read-only and separate from migration:
it does NOT quiesce writers, provide a backup, close the race to a concurrent
legacy write, or promise that every later migration failure is atomic. Fresh
recoverable backups and a demonstrated write freeze remain mandatory. Populated
legacy feature data needs an explicit preservation/migration plan, not an
exception flag or automatic deletion. Production data changes still require the
owning approval and recovery procedure.
